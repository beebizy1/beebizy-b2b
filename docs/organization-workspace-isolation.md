# Organization access and internal administration

## Requested outcome

Internal Beebizy staff use a separate administrative dashboard for organization setup, user activity and pilot feedback. Customer Studio navigation does not contain those tools. Pilots receive organization-specific sign-in links and see only their authorized workspace and its configured event tools. Organization mode tracks vendor costs; planner mode additionally tracks client charges and margins. Existing data and public event links must be preserved.

## Investigation

- User activity already has an API operator guard, but is placed in the customer Studio shell for staff demonstrations.
- Carlin belongs to Page One Events (`ws_8317936b69f14b49bab3`); Radhika belongs to CCS (`ws_7e3ad48b86044af59f0c`). These are already separate workspaces.
- One SCU pilot is a member of the Beebizy team workspace. That workspace has one `santa-clara` event and sixteen standard events in the morning backup. Its SCU event has 912 registrations. This legacy arrangement needs a planned atomic separation; do not delete memberships or move a partial record set.
- `authorize` currently accepts a Clerk organization header without tying it to the verified session. Close that trust gap.
- New vendors from an event form are created then booked in separate requests; a failed second request can leave a directory-only vendor. Global directory creation has no event picker. Vendor updates invalidate the directory but not existing event booking caches.
- Budget, Run of Show and Payments derive vendor rows from event bookings. Checklist does not currently derive vendor setup tasks.

## Implementation decisions

- Separate `/internal` routes and shell, protected by verified operator identity on both the UI and API. Preserve old admin links through guarded redirects. Remove activity and feedback entries from customer navigation and command palette.
- Organization entry links use `/organization/:workspaceId`. The URL is a selector, never a credential. Server-side membership determines the workspace, role, scope and subscription. The sign-in flow preserves the intended organization route.
- Selected organization is scoped per user and browser tab. Each authenticated workspace gets its own query client and cache identity so switching cannot display another organization's cached data or drafts.
- Add an additive workspace product profile: planner/organization and optional enabled event tabs. Legacy profiles preserve existing presentation until explicitly configured. Only internal operators publish organization profiles.
- Internal organization administration lists existing workspaces, copyable sign-in links, counts and profile controls. New organizations can be created with explicit pilot access without sending email automatically.
- Use complete, revision-fenced private drafts for organization profile/create forms. Publishing profile changes and granting invitations remain explicit actions.
- Make event association visible when creating a vendor. Protect partial failures/retries and keep contact/cost updates synchronized across dependent views. Add linked vendor preparation items to Checklist without duplicating or silently completing manual tasks.
- Do not introduce new paid services or billing changes for this work. Preserve the recovered Neon database and existing registrations.

## Verification required

Use separate named QA workspaces/events. Plan the legacy SCU separation against the complete dependency graph and verify counts/references before and after in one transaction.
